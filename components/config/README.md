# `config`

Config values for the wasi:config/store interface, served from a list of key value pairs.

## Interfaces

Imports:

- `componentized:constants/config-values@0.1.0`: the key value pairs to serve, e.g. from a constants component

Exports:

- `wasi:config/store@0.2.0-rc.1`: gets config values from the imported key value pairs

As with the WIT `map` type, the last pair with a key wins: `get` returns the value of the last pair with the key. `get-all` returns every pair, in order, including duplicate keys. Neither returns an error.

## Size

The component is optimized for size, about 5KB compared to 25KB built with the defaults:

- Built without `std`, with a panic handler that traps rather than formatting a message. Nothing in the component is expected to panic, if it does the call traps without a message.
- A bump allocator in place of `dlmalloc`. Memory is reused once every allocation is freed, which happens at the end of each call as nothing is kept between calls. Changes that keep values across calls, e.g. a cache, need a general purpose allocator, otherwise memory grows with every call.
- Built with the `component` profile, optimizing for size with LTO and stripped symbols, and then with `wasm-opt -Oz`.

> [!CAUTION]
> These optimizations have only been tested with `config-values` provided by a component generated by `constants`.
